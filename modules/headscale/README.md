# Headscale

This markdown really only exists to remind me what/how I've done here.

Targets headscale 0.29.x (as pinned by nixpkgs).

## Opinions Applied Here

In this config, there's a few things to be wary of:

- preauth secrets are expected to be stored in `secrets/tailscale` at the top of the repository
- keys are tagged (`tag:<name>`) so devices register as tagged devices — headscale 0.28+ requires every pre-auth key to be either user-owned or tagged (never neither), and these namespaces are all infrastructure, so tags win
- because keys are tagged, registered nodes never expire (tagged devices are exempt from key expiry)
- ACL rules are written as nix rather than JSON to keep the repo nix'd, emitted in the policy v2 format (v1 support was removed upstream in 0.27)
- because the acls reference tags, the policy also emits a `tagOwners` entry for each tag (every tag used in acls must be declared there since 0.28, or headscale refuses to start); each tag is owned by a placeholder `admin@` user — no user row is created, and the v2 parser accepts a user that has not registered yet (it resolves to an empty set)
- keys are provisioned by a oneshot systemd unit (`headscale-preauth-setup`) that inserts them directly into the sqlite database using the legacy plaintext format (still accepted for backwards compatibility)

## Notes

- this module assumes a fresh database: headscale 0.29 removed all migrations
  prior to 0.28 and enforces a one-minor-at-a-time upgrade path, so older
  databases cannot be upgraded in place
- preauth keys are set to never expire (NULL expiration); if you need to rotate
  a key, update the agenix secret, restart `headscale-preauth-setup.service` to
  insert the new key, and delete the old key row (the unit only inserts, it does
  not revoke) — e.g. `headscale preauthkeys expire --id <ID>` — noting your
  clients will de-auth until you also roll their secrets
- the old `users`/namespaces concept is gone; the key `name` is now just a
  label used to derive the tag and locate the secret file
- the noise private key is auto-generated by headscale at
  `/var/lib/headscale/noise_private.key` (the previous explicit path matched
  the nixpkgs module default and was dropped)
